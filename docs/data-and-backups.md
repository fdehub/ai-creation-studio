# 保存与备份

## 保存作品

作品按 ID 独立排队保存，同一作品的写入串行执行。顶部显示待保存数量与失败信息，可点击“保存作品”立即提交。

未提交草稿保存在当前浏览器的 IndexedDB。重新打开页面时，如果草稿与后端版本不同，可以恢复草稿或保留后端版本。清除站点数据会清除草稿；复制服务器数据目录不会备份浏览器草稿及聊天记录。

尚未保存或本地草稿写入未完成时，关闭页面会触发浏览器提示。退出前请等待保存完成；强制结束进程、断电等情况无法保证最后一次按键已落盘。

## 正文与大纲保护

- 后端在正文变化前保留最近 20 个版本，可通过“历史版本”恢复；版本会滚动淘汰，不能代替独立备份。
- 润色、扩写和缩写完整接收非空结果后才替换原文；失败或取消保留原文。
- 新结构先生成预览；应用时保留现有正文、章节 ID 和多余章节。
- 重新推演和续传会检测生成期间的编辑，避免覆盖新内容。
- 切换作品或离开页面会取消相关等待；取消本地等待不保证供应商已停止处理或计费。

建议同一作品只在一个页面中编辑；当前不提供跨页面协作或版本冲突合并。

## 备份数据

数据目录默认为 `backend/`，可通过 `NOVEL_DATA_DIR` 修改。需要保留：

| 内容 | 用途 |
| --- | --- |
| `ai_novel.db` | 作品、正文历史版本、漫剧全剧设定、制作草稿与已应用分镜 |
| `backups/` | 旧数据库增加漫剧设定字段前的自动备份；仍需自行做日常备份 |
| `memory.db` | 作品内检索索引 |
| `uploads/` | 素材图片；旧 blob URL 图片需要重新上传 |
| `credentials/` | 加密平台账号会话及其保护信息，属于敏感数据 |

先停止前后端，再将数据文件、素材和账号目录复制到安全位置；恢复时也先停止服务。也可将整个数据目录保存在仅自己可访问的位置，但不要提交到 Git。

Windows 账号凭据由当前系统用户的 DPAPI 保护，不能仅靠复制文件直接迁移到其他机器或系统用户；迁移作品后请重新连接平台账号，详见 [凭据存储](accounts.md#凭据存储与权限)。

现有 `backend/` 数据库继续使用，根目录的旧同名数据库不会自动合并。旧版无作品归属的检索记录不会混入新的作品索引。

漫剧草稿每个成功阶段都会保存，应用前保留原分镜。仅更新分镜进度、设定或审阅记录不会滚动淘汰正文历史版本。首次升级旧数据库时会先备份再添加字段，备份位于数据目录 `backups/before-comic-production-*.db`。详见[漫剧制作](comic-production.md)。
